How other tools solve the central-library problem

One source of truth, many consumers, everyone wanting to change something locally. GitHub, Figma, Sketch, Adobe CC, Contentful, Salesforce, AEM, Crowdin and Qualtrics have all answered this — here is what they landed on, and which parts are worth stealing for Question Management.

The shared anatomy

Every library system is five beats.
Tools only differ on the last three.

GitHub, Figma, Sketch, Adobe CC, Contentful, Salesforce, AEM, Crowdin and Qualtrics all solve the same problem: one source of truth, many consumers, each of whom wants to change something locally. Strip the branding away and they run the same pipeline.

1

Author

Someone owns the canonical item and edits it in one place.

Who is allowed to touch the source?
2

Publish

A deliberate, versioned release. Editing the source is not the same as shipping it.

What's in this release, and who signed it off?
3

Consume

The project takes a copy, or keeps a live link back to the source.

Does the consumer keep a pointer home?
4

Diverge

Local reality differs. Someone overrides a value, or cuts the cord entirely.

What may be changed locally, and what is locked?
5

Reconcile

The centre changed. So did the local copy. Now what?

Who wins, when, and who gets to decide?
The whole design space lives in beats 3–5. Beat 1 and 2 are just permissions and a publish button. Every difference between GitHub, Figma and a CMS is a different answer to: link or copy · what may be overridden · what happens on collision.
Beat 3 — Consume

The single biggest decision: how strong is the cord?

There are only three answers, and every tool is one of them (or lets you choose per item). Strength of the link is inversely proportional to local freedom — that trade is unavoidable, so make it consciously.

A · No link

Copy / snapshot

You take the library version once. From that second on, the two are strangers.
GitHub “Use this template” Qualtrics library copy Canva brand template Strapi “Fill in from another locale” Git subtree (squashed)
Local editsAnything. Nobody is watching.
Central updateNever arrives. There is no channel.
Decided byNobody — one moment, then drift.
The billDrift is invisible and permanent. A typo fix means hunting down N copies by hand. Comparability across projects quietly dies.
B · Link, consumer pulls

Linked, opt-in updates

The link stays. The centre can only offer a new version; the consumer accepts it when ready.
Figma “Updates available” → Update all Sketch “Component Updates Available” npm range + lockfile + Dependabot PR GitHub fork → “Sync fork” git submodule (pinned SHA) Contentful environment alias
Local editsPreserved as overrides — rules vary wildly.
Central updateQueued as a proposal, with a diff.
Decided byThe consumer, on their own clock.
The billFleet fragmentation. A consumer can sit on a three-year-old version forever, and you can't see who's on what without analytics.
C · Link, centre pushes

Live / forced sync

The centre writes straight through to every consumer. Usually paired with heavy locking.
Adobe CC Libraries (linked assets) Qualtrics Reference Survey (read-only) AEM Live Copy “Rollout” Salesforce push upgrade Locked / “developer-only” fields
Local editsBlocked, or silently overwritten.
Central updateInstant, everywhere, no consent.
Decided byThe library owner. Alone.
The billZero local authority, so people fork out of the system entirely to get their edit. One bad publish hits everyone at once.
Nearly every mature system is B, with deliberate escape hatches into A and C. Figma: linked instances (B) + “Detach instance” (A). AEM: rollout (C) + “Cancel inheritance” (B) + “Detach” (A). The useful question is not which one — it's which parts of an item sit in which lane. Wording locked (C), help text overridable (B), notes free (A).
Beat 4 — Diverge

Three states, and one of the doors only opens one way

Everyone converges on the same three states. What separates a good system from a painful one is whether the middle state exists at all, and whether you can get back out of it.

1 · Linked

Consumer holds a reference. Every value comes from the library. Nothing local to lose.
Figma instance of a main component
Git branch in sync with upstream
AEM live copy, inheriting
Contentful field left empty → falls back
Sitecore clone showing [original value]
edit one property
“Reset all changes” · “Accept the change” · clear the field

2 · Overridden

Still linked. Inherits everything except the properties you touched. This is where 90% of real work lives.
Figma instance overrides (text, fill, swap)
AEM “Cancel inheritance” / “Suspend”
Salesforce “both can edit” component
ServiceNow customized baseline record
Contentful non-empty child locale value
detach / make local
usually impossible

3 · Detached

Cord cut. It's your object now. No updates, no lineage, no reporting on it.
Figma “Detach instance” ⌥⌘B
Sketch “Make Local”
AEM “Detach” — permanent
GitHub leave the fork network — “cannot be reconnected”
Sitecore original deleted → clone becomes a normal item
Two rules that fall straight out of this. (1) Override must be reversible and detach must be scary — every tool that got this backwards created a graveyard of orphans nobody can audit. (2) Override should be recorded as a delta, not a copy. Contentful's version is the most elegant: a child value that is empty inherits, a child value that is filled overrides. Clearing the field re-inherits automatically — no “relink” button needed. The cost: “inherited” and “deliberately blank” become indistinguishable.
Beat 5 — Reconcile

The centre changed something you had already overridden. Five ways out.

This is the moment the whole design is really about, and there are exactly five strategies in the wild. Most products pick one globally; the better ones pick per field type.

POLICY 1

Overwrite

Central wins, silently. Your local edit is gone at next sync.

AEM rollout (unless inheritance was cancelled). git submodule update --force. Sync fork --force.
+ Guarantees consistency − Destroys work without asking
POLICY 2

Skip & freeze

Local wins — and that item quietly stops receiving updates. Forever.

Salesforce: once a subscriber edits a “both can edit” component, vendor changes only reach new installs. ServiceNow: customized records are skipped on upgrade.
+ Never destroys local work − Silent zombies: items nobody knows are stale
POLICY 3

Ask, per item

A non-blocking notice appears on exactly the field that diverged: review the original · accept the change · reject the change.

Sitecore clones. Figma's update tray is the coarser, per-asset version.
+ Best UX; keeps a human in the loop − Expensive to build; needs a readable diff
POLICY 4

Keep it, revoke its status

The value survives — but the badge it earned does not, and it drops back into a review queue.

Crowdin: source string changes → translation kept, approval revoked. SurveyMonkey: edit a certified question → certification badge falls off. Culture Amp: reword outside the approved variant list → loses benchmark.
+ Doesn't block anyone; consequence is visible − Needs a status worth losing
POLICY 5

Merge & conflict

A real three-way merge. Clean parts apply automatically; genuine clashes stop and demand a human.

Git. Figma branching (Org/Enterprise) — but all-or-nothing, no cherry-picking.
+ Handles simultaneous change properly − Only works if the diff is legible to a non-engineer
Policy 4 is the one most teams never consider, and it's the strongest fit for a content library. Don't lock the item and don't silently overwrite it — let people edit, then take away precisely what the edit invalidated: the benchmark, the translation approval, the “certified” mark, the cross-client comparability. The edit is allowed; the claim is not.

The centre never pushes. A bot opens a reviewable change with a diff, a changelog and automated checks — so “should we take v5?” becomes a normal decision with evidence, not an interrupt. The failing check is the pattern to copy: automated impact analysis attached to the update itself.

Applied

Six things worth stealing for a question library

Not a proposal — a checklist of the patterns that survive contact with the specific problem of shared, comparable, translated content.

1 · Lane it per property, not per item

A question isn't one object. Its wording and scale carry comparability and should be locked or push-synced. Its translation, help text, category and internal notes can be freely local. One item, three lanes.

Salesforce manageability rules · AEM per-component inheritance

2 · Editing the source ≠ shipping it

Keep a hard publish step with a checklist of what's included and a free-text “why”. If a library owner can change a live question by typing, you have no governance.

Figma publish modal · Qualtrics publish gate

3 · Let people edit; take away the claim

Never block a reword. Instead: reworded question loses its benchmark, its translations drop to “needs review”, and it's flagged as no longer comparable. The consequence is visible and self-explaining.

Crowdin approval revoke · SurveyMonkey certification · Culture Amp benchmarkable variants

4 · Publish approved variants, not just one wording

Culture Amp's move: instead of one locked string, ship a short whitelist of alternative wordings that are still benchmarkable. Most local-change requests get satisfied inside the comparability envelope.

Culture Amp alternatives table

5 · Show the ghost value

Wherever something is overridden, keep the library value visible next to it. It's what makes “reset” safe to offer and makes drift auditable at a glance.

Sitecore [original value] · Contentful fallback preview · Figma side-by-side diff

6 · Build the fleet view before you need it

The failure mode of pull-based sync is that nobody knows who's on what. A table of every consumer, its version, and its overrides is the thing you'll wish you had in year two.

AEM Live Copy Overview · Figma design-system analytics · Renovate dependency dashboard
The one decision that determines everything else: is a question in a survey a reference to the library item, or a copy of it? Reference gives you fleet-wide fixes, real analytics and comparability, at the cost of building overrides, conflict UI and versioning. Copy gives you all of that for free today and none of it in three years. Every tool on this board that started with copy — Qualtrics, SurveyMonkey, Canva — eventually had to bolt a second, linked mechanism on beside it.
